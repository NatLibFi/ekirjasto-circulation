# Text search options

The existing `/search` and `/search/<lane_identifier>` routes accept two optional
parameters for text searches. Existing clients can omit both parameters: the
default query, response format, analyzers, and index schema are unchanged.

| Parameter | Default | Accepted values |
| --- | --- | --- |
| `search_field` | `all` | `all`, `title`, `author`, `classification`, `genre`, `summary` |
| `include_summary` | `true` | `true`, `false` |

Examples (append to the library's search URL):

```text
?q=erotiikka&include_summary=false
?q=erotiikka&search_field=title
?q=erotiikka&search_field=genre
?q=dog&search_field=summary&language=eng
```

`search_field=all` uses the existing multi-field search. Setting
`include_summary=false` removes the description (`summary`) from that search,
including any recursive queries generated by the query parser. It does not
exclude books that also contain the search term in their description.

A specific `search_field` searches only that field and takes precedence over
`include_summary`. Thus `search_field=summary&include_summary=false` still
searches the description. Field-only searches do not interpret genre, audience,
or age words as additional filters. Title search excludes subtitles. Author
search includes the primary author and contributors with primary-author or
author roles, excluding narrator-only contributions.

Classification searches use the existing analyzed `classifications.term` field.
Genre searches use the existing nested `genres.name` keyword field, which matches
a complete genre name with the index's case and accent normalization. Genre
names are not tokenized into individual words. The available names and
classification terms depend on imported metadata; these parameters do not
translate them or provide a list of selectable values.

Existing language, availability, collection, distributor, and ordering options
can be combined with these parameters. Field-only searches do not apply the
default score cutoff used when sorting multi-field search results by metadata;
that cutoff is not calibrated for single-field scores. An explicitly supplied
internal minimum score is still respected.

The active options are retained in search feed URLs and facet navigation.
Unsupported fields, malformed boolean values, or non-default text search options
combined with `search_type=json` produce an invalid-input response (HTTP 400).
Existing JSON searches remain unchanged.

## Genre and classification checkboxes

`GET /search_filter_values` returns genre and classification options present in
the library's searchable books. Each value includes a count of distinct books.
The result is cached for one hour per library collection set. Values with no
searchable books are omitted.

Send selected options as repeated parameters alongside the search:

```text
?q=erotiikka&genre=12&genre=27&classification=Romance&classification=Erotica
```

Selected genre IDs are ORed with each other, as are selected classification
terms. Selecting at least one genre and at least one classification requires a
book to match a selected genre and a selected classification (AND between the
groups). These filters apply with either `search_field=all` or a field-scoped
text search. Genre values use IDs; classification values use the indexed term.
Currently, only classification schemes indexed for search are returned.

No reindexing is required. Applications must add their own controls and send the
new parameters to expose these options to users. For example, show a "Search in"
selector and offer an "Include descriptions" toggle when "All fields" is selected.
